# Bigimong v0.17 Free Blender Character Pilot Design

Status: approved in chat on 2026-09-15. Written specification awaits final user review before implementation planning.

## Goal

Replace the rejected primitive-only character stand-ins with a zero-paid-API asset pipeline. The first release produces five visually reviewed, mobile-ready 3D assets: the masculine and feminine base avatars plus the baby, teen, and adult red Tyrannosaurus. After the pilot passes visual and Unity checks, the same pipeline expands to 30 characters across three growth stages, for 90 dinosaur assets in total.

The supplied Bigimong avatar, roster, evolution, home, egg, loading, and AR reference artwork remains the visual authority. Front and three-quarter identity must follow the references closely. Surfaces not visible in the references are inferred from the visible palette, clothing, anatomy, and accessory language and remain subject to user review.

## Confirmed sequence

1. Build and review the five-model pilot.
2. Import only accepted pilot models into Unity and build an installable v0.17 candidate APK.
3. Review in-game captures on an Android phone.
4. Expand the accepted construction rules to all 90 dinosaur stage assets in small review batches.

## Cost and service constraints

- Do not call Tripo, Fal, or any other billable 3D or image generation endpoint.
- Do not require DigitalOcean or another paid server.
- Generate assets with Blender running in the existing public GitHub repository's Actions workflow. The workflow must not contain credentials.
- Keep `art/tripo/v0.16-pilot-jobs.json` disabled as an archival alternative; it is not part of the free path.
- If the repository's hosted runner is unavailable or quota-limited, fail clearly and retain all source scripts so the same command can run on any computer with Blender installed.

## Approaches considered

### Selected: scripted Blender asset build

A deterministic Blender Python script builds continuous stylized meshes, embedded PBR/toon textures, an armature, named actions, mobile exports, and fixed-camera review renders. GitHub Actions supplies Blender because the current local workspace does not have Blender installed. This produces inspectable FBX/GLB assets and avoids paid inference services.

### Rejected: Unity runtime primitive generation

This is free and already works as a fallback, but the user rejected its sphere-and-capsule appearance. Runtime generation is less controllable, increases device work, and cannot satisfy the required visual-review gate.

### Rejected: adapting unrelated free character packs

Third-party packs may be free of charge, but their licenses, proportions, topology, and accessories would not match Bigimong reliably. No third-party character mesh is introduced by the pilot.

## Pipeline architecture

### Reference manifest

Create `art/free3d/v0.17-pilot.json` as the single source of truth for the five models. Every entry records:

- stable ID and Unity resource name;
- authoritative source artwork path and source hash;
- target real-world height;
- front silhouette landmarks and body ratios;
- required colors, clothing, accessories, and separate animation parts;
- triangle, material, texture, bone, and action limits;
- whether unseen rear details are explicit or inferred.

The manifest validator rejects duplicate IDs, missing references, unsupported stages, unapproved output names, and any external paid endpoint or enabled billing flag.

### Blender builder

Create `scripts/blender_generate_bigimong.py`. It will run in Blender background mode and construct each asset from custom profiles, curves, metaball/remesh surfaces, and explicitly generated topology. The final body and head use joined and remeshed continuous surfaces, not a visible assembly of stock Unity spheres and capsules.

Eyes, pupils, highlights, teeth, hair masses, clothing, medallion, hats, backpack, rolled mat, and other attachment points stay as named meshes where separation is useful for animation or customization. Surface intersections, floating parts, open boundaries, and hidden duplicate faces are rejected before export.

Each model receives:

- smooth normals and mobile-safe subdivision;
- UVs and an embedded 1024×1024 RGBA texture atlas;
- soft toy-like PBR values with no realistic pores, scales, gore, or sharp violence;
- a humanoid or dinosaur armature with deterministic bone names;
- automatic weights followed by scripted weight corrections for eyes, jaw, hands, feet, tail, clothing, and accessories;
- named actions for `Idle`, `Summon`, `Attack`, `DodgeLeft`, `DodgeRight`, `Hit`, `Knockout`, and `Victory`;
- a root origin at the lowest ground-contact point, with ground contact at `Z=0`.

### Validator and review renderer

Create `scripts/validate_free3d_assets.py` and Blender-side validation helpers. Validation checks file existence, root name, dimensions, origin tolerance, triangle count, materials, texture packing, required bones, required actions, non-empty meshes, finite transforms, and attachment names.

The builder renders front, left, rear, right, and three-quarter PNGs with a fixed orthographic camera, neutral studio light, transparent background, and a visible scale marker. It also writes a JSON report containing Blender version, source hashes, output hashes, mesh statistics, bounds, action list, warnings, and validation results.

No automated score may declare visual completion. The rendered contact sheet and an actual Unity capture must be reviewed against the supplied images.

### GitHub Actions workflow

Create `.github/workflows/build-free-3d-pilot.yml` with these ordered jobs:

1. Validate the manifest and source hashes.
2. Install the repository-supported Blender version on the hosted Linux runner and record the exact version.
3. Generate the five models and animations in background mode.
4. Run geometry, texture, rig, action, and performance validation.
5. Upload FBX, GLB, textures, four-direction renders, contact sheets, and the JSON report as a review artifact.

Failed validation prevents model publication and Unity integration. The workflow never calls external model-generation APIs.

### Unity integration

After visual approval, place the accepted FBX files under:

`unity/BigimongAR/Assets/BigimongAR/Resources/GeneratedCharacters/`

Use the existing stable names:

- `Avatar_Masculine`
- `Avatar_Feminine`
- `Bigimong_01_Baby`
- `Bigimong_01_Teen`
- `Bigimong_01_Adult`

Unity imports them as GameObjects and the existing `Resources.Load` boundary selects them before `ProceduralAvatarFactory` or `ProceduralDragonFactory`. Add an editor importer that maps clips, materials, scale, root motion, and attachment anchors consistently. The procedural models remain only as an explicit missing-asset fallback and do not count as visual completion.

| Asset | Height | Required identity |
| --- | ---: | --- |
| Masculine avatar | 1.65 m | Oversized rounded head, very large warm-brown layered eyes, thick dark brows, small rounded nose, rosy cheeks, gentle smile, five swept chocolate hair locks, charcoal sleeveless top and shorts, proportional hands and bare feet, gold summoning medallion |
| Feminine avatar | 1.62 m | Same family and eye language, slimmer brows, chin-length chocolate bob with side fringe and curled tips, charcoal sleeveless top and shorts, proportional hands and bare feet, gold summoning medallion |
| Tyrannosaurus baby | 0.30 m | Rounded red body, cream muzzle and belly, huge brown eyes, four readable rounded teeth, short limbs and tail, yellow explorer cap, curious happy expression |

Growth stages use different body ratios and wardrobe. Uniformly scaling one Tyrannosaurus mesh into three sizes is prohibited.

## Mobile budgets

- Maximum 30,000 rendered triangles per character, including accessories.
- Target 18,000–25,000 triangles for each pilot model.
- One 1024×1024 texture atlas per character; a second small emission texture is allowed only for the medallion.
- Maximum four material slots per character.
- Maximum 64 deform bones and 16 non-deforming attachment/control bones.
- One active character animator per side during AR battle.
- LOD1 is generated at approximately 55% of the accepted triangle count for later 90-model expansion.

## Runtime motion and battle behavior

- Home characters loop subtle breathing, eye blinks, head turns, and weight shifts using unscaled time where appropriate.
- The avatar's medallion remains attached to the neck until the summon action detaches it to the existing throw trajectory.
- The dinosaur emerges from the magic circle with a scale-and-height reveal, dust/shockwave code VFX, and a short landing reaction.
- Existing button press motion, AR placement, battle input, surrender-to-home cleanup, and no-reward surrender behavior remain unchanged.
- Existing code-generated elemental VFX stays in use; no copyrighted third-party effect images are copied.

## Failure handling

- Missing or hash-mismatched reference: stop before Blender generation.
- Blender script error or invalid mesh: fail the asset workflow and keep the last accepted models untouched.
- Budget, rig, action, or origin violation: generate a report but do not mark the artifact accepted.
- Unity import failure: fail editor tests and do not start the APK build.
- Missing accepted asset at runtime: show the procedural fallback and record a development warning; never describe that screen as final reference-matched art.
- Hosted-runner failure: preserve the reproducible command and retry only after the cause is known; do not switch to a paid service automatically.

## Verification and acceptance

The pilot is complete only when all of the following pass:

1. Node tests validate manifest rules, paths, stable names, paid-service prohibition, and workflow contracts.
2. Blender self-tests generate a small fixture and confirm origin, bounds, texture packing, FBX/GLB export, bones, and actions.
3. All five production assets pass the geometry and mobile reports.
4. Front, left, rear, right, and three-quarter renders are available for every model.
5. The user approves the pilot contact sheets against the supplied references.
6. Unity editor tests load all five stable resource names and verify scale, animator clips, materials, and attachment anchors.
7. A Unity Android ARM64 APK builds, passes the existing package/signature checks, and launches on the user's phone.
8. In-game captures show the accepted models in avatar selection, home idle, summoning, and AR battle.

Code tests or APK compilation alone do not constitute visual acceptance.

## Stage two: 90 dinosaur assets

After the five-model pilot is accepted, add species-specific body plans and stage profiles to the manifest-driven builder. Produce the 90 assets in review batches rather than one unreviewed dump. Each batch must pass the same render, mobile, Unity, and APK gates before becoming the accepted catalog.

The seven species shown in the three-stage evolution poster use that poster as stage authority. Other stage views are derived from the catalog artwork and the accepted growth-language rules; inferred rear or stage details are labeled in reports so they can be revised without changing runtime identifiers.

## Deliverables

Pilot review artifact:

- five FBX files;
- five GLB files;
- embedded or adjacent texture atlases;
- five multi-angle contact sheets;
- animation preview renders;
- one machine-readable validation report;
- one Blender review scene.

Accepted v0.17 application deliverable:

- source and deterministic asset workflow on `feature/v0.12-offline-beta`;
- five accepted Unity character resources;
- Unity editor validation results;
- installable `Bigimong-AR-v0.17-debug.apk` with SHA-256 and verification JSON.

The 90-model expansion begins only after the pilot's actual renders and in-game captures are approved.
