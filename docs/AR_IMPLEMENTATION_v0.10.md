# 비기몽 AR 전투 구현 기록 v0.10

## 유지한 확정 규칙

- Kotlin·Compose는 계정·걸음·BLE·서버 통신, Unity는 전체화면 AR 전투를 담당한다.
- BLE는 8자리 페어링 코드 교환에만 사용한다.
- 근거리 대전 참가비는 양쪽 1,000비기이며 판정·HP·정산·20% 소각은 서버 권위로 처리한다.
- 각 라운드는 서버 기준 10초이며 미선택·통신 지연 시 서버 자동 선택을 사용한다.
- Cloud Anchor를 사용할 수 없을 때는 각 단말의 로컬 링에서 동일한 서버 결과와 타이밍을 재생한다.

## v0.10에서 보강한 기능

### 실제 크기 보존

v0.9는 납작한 원기둥 링 프리팹 자체를 전투 루트로 사용했다. 이 구조에서는 자식 캐릭터가 링의 Y축 스케일을 상속할 수 있었다. v0.10은 스케일이 1인 빈 전투 좌표 루트를 만들고 링 비주얼만 자식으로 분리한다. 캐릭터는 별도 좌표 루트 아래에서 Renderer Bounds를 기준으로 0.3m·0.9m·2.1m 높이를 유지한다.

가장 큰 캐릭터의 높이에 맞춰 링 직경을 1.6~5.0m 범위에서 자동 조절한다.

### 서버 시간 기준 턴 표시

전투 응답에 `serverNow`를 추가했다. Android는 `serverNow`와 `deadlineAt`을 Unity로 전달하고 Unity HUD는 두 값의 차이를 `Time.realtimeSinceStartup`에 연결한다. 단말의 시스템 시계가 서버와 달라도 남은 시간이 흔들리지 않는다.

### 재접속 스냅샷 복구

Unity 액터는 서버 스냅샷의 양쪽 HP를 애니메이션 없이 즉시 반영할 수 있다. 통신이 끊긴 동안 여러 라운드가 자동 진행됐더라도 최신 HP와 승패가 최종 기준이 된다.

Android는 새 라운드 연출 메시지를 먼저 보내고 그다음 권위 스냅샷을 보낸다. Unity는 공격 후 0.18초에 회피·피격을 재생하고, 연출이 끝난 뒤 보류한 스냅샷으로 상태를 보정한다. 중복되거나 오래된 라운드 번호는 다시 재생하지 않는다.

### HUD와 공유 앵커 복구

- 양쪽 HP, 현재 라운드, 피해·회피 결과를 AR HUD에 표시한다.
- 공격자나 방어자의 입력이 서버 자동 선택이면 `서버 자동선택`을 표시한다.
- 앵커 다시 잡기를 실행하면 진행 중이던 이전 Host/Resolve 콜백을 세대 번호로 무효화한다.
- 호스트는 새 로컬 링을 놓은 뒤 새 Cloud Anchor ID를 서버에 다시 등록할 수 있다.

## 검증 결과

- Node 정적·통합 테스트 47개 통과
- 서버 권위 판정, 10초 자동 선택, 1,000비기 근거리 예치, 20% 소각 규칙 유지
- 서버 응답의 `serverNow` 포함 및 `deadlineAt >= serverNow` 검증
- Unity 프로젝트 구조, 링/액터 스케일 분리, 스냅샷 복구, 모션 순서, 단조 시간 카운트다운, 앵커 콜백 무효화 검사

Unity Editor와 ARCore 실기기는 현재 실행 환경에 포함되지 않아 실제 카메라·Cloud Anchor 2기기 검증은 남아 있다. `SharedAnchorProvider`의 ARCore Extensions 구체 구현에는 Google Cloud 프로젝트 설정이 필요하다.
